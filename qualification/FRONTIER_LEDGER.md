# PCSS finite frontier ledger

This ledger is frozen before comparative native-server arm results. A changed
protocol creates a new study and does not replace earlier evidence.

## Retrieval families

1. Conservative exact persistent suffix plus exact current-context sequence.
2. Consensus/negative-evidence variant, only if family 1 misses the practical
   calibration gate because ambiguous persistent continuations are measured.
3. Bounded structural/source-anchor family, only with an owner-authorized
   source-buffer API and a preregistered independent workload.

No fourth retrieval family is permitted in this campaign. Threshold-only
changes do not create a new family.

## Causal implementation interventions

1. Successful-end learning instead of accepted-draft-only learning.
2. Disk-resident token payloads with a bounded exact-verification index.
3. Correct current-context continuation anchor plus per-request negative
   evidence suppression.

These are development interventions completed before the first frozen
comparative study. They are not post-hoc benchmark tuning.

## Finite configuration grid

- Draft maximum: `{4, 8}` on calibration only; default candidate is 8.
- Exact prefix maximum: `{32, 64}` on calibration only; default candidate is 64.
- Lookup probe ceiling: fixed at 256.
- Lookup byte ceiling: fixed at 256 KiB.
- Persistent policy: disabled, exact persistent, exact persistent plus current
  context.

The grid cannot expand after calibration results become visible. The owner
holdout, if later supplied, is opened once after one candidate is frozen.

## Eviction, storage, and write scheduling

- FIFO is comparison-only.
- Production eviction families: bounded recent-use utility, then at most one
  accepted-utility variant if eviction is a measured bottleneck.
- Storage backend: current append-only checksummed segments. At most two
  alternatives may be evaluated, only after a measured storage/index ceiling
  failure.
- Write scheduling: successful-end synchronous append. At most two alternatives
  may be evaluated, only if endpoint update latency materially violates the
  frozen gate.

## Stop rule

Stop the campaign when all permitted families are decided, a correctness gate
fails without a safe causal fix, resource/thermal kill gates fire, or no
remaining item can change the product decision. Synthetic controls never
authorize a representative speedup or default-enable claim.
